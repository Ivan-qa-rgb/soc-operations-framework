# Synthetic Data Policy

Все данные в этом репозитории являются синтетическими и предназначены
исключительно для обучения, демонстрации и построения портфолио.

## Назначение

Репозиторий используется для:

- практики SOC L1/L2/IR;
- построения incident timeline;
- разработки Sigma-детектов;
- создания runbooks и PIR-шаблонов;
- демонстрации подхода к корреляции EDR, IdP, proxy и DNS;
- подготовки к tabletop-упражнениям.

## Что разрешено

В репозитории разрешены:

- синтетические имена пользователей, например `d.petrov`;
- вымышленные хосты, например `PAY-WKS-07`;
- вымышленные компании, например `SynthPay`;
- документационные IP-диапазоны RFC 5737:
  - `192.0.2.0/24`;
  - `198.51.100.0/24`;
  - `203.0.113.0/24`;
- домены с зарезервированным суффиксом `example`;
- синтетические хэши, например строки из нулей или единиц;
- учебные Sigma-правила и шаблоны IR-документации.

## Что запрещено

В репозиторий нельзя добавлять:

- реальные IP-адреса;
- реальные домены, поддомены и URL;
- реальные email-адреса;
- реальные ФИО, телефоны, идентификаторы сотрудников;
- реальные пароли, API keys, OAuth tokens, session cookies и SSH keys;
- реальные хэши вредоносных файлов;
- реальные названия компаний, клиентов или внутренних систем;
- скриншоты с реальными данными;
- экспорты SIEM, EDR, IdP, proxy или DNS, содержащие реальные события.

## Правила коммитов

Перед каждым commit необходимо проверить:

- нет файлов с расширениями `.pem`, `.key`, `.pfx`, `.p12`, `.kdbx`;
- нет файлов `.env`, `.env.*`;
- нет папок `secrets/` или `credentials/`;
- нет токенов, cookies, паролей и приватных ключей;
- нет реальных доменов и IP;
- нет персональных данных;
- все хэши синтетические;
- все имена и события вымышленные.

## Если секрет попал в репозиторий

1. Немедленно отозвать секрет в исходном сервисе.
2. Не считать удаление файла достаточной мерой: секрет может остаться
   в истории Git.
3. Создать новый секрет и обновить все зависимые системы.
4. Проверить историю коммитов и при необходимости обратиться в GitHub Support.
5. Зафиксировать инцидент и провести разбор.

GitHub рекомендует использовать Secret Scanning и Push Protection, чтобы
предотвратить случайную публикацию credentials в репозитории.
